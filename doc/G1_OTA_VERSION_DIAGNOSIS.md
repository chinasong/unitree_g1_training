# G1 版本查询 104 与 23 自由度模式匹配

2026-10-21，北京时间（UTC+8）。本轮只读检查；机器人仍按用户报告为靠柜坐地、双脚贴地。报告不证明足底、臀部或柜体的载荷。

**104 的探测故障已修正；运动主机固件版本仍未知，尚不能选择本机起身路线。**

## 原因与实机验证

旧探测脚本将 `-T 3` 当成 3 秒。实际本机 `ota_pipe_cli` 按微秒处理，TCP 接收的 `SocketHelper::WaitRecv` 在 `0x36a3e4…0x36a418` 将参数除以 1000，再交给以毫秒计时的 `poll`：原参数得到 0 毫秒等待。

同一程序 SHA256、同一启动周期、同一 `default` 端点的对照结果：

| 查询 | 退出码 | 结果 |
|---|---:|---|
| `listmoduleversion -T 3` | 104 | 未取得模块列表 |
| `listmoduleversion -T 3000000` | 0 | 返回 PC4 三个模块 |
| 修正后的项目脚本再次查询 | 0 | 同一 PC4 三模块列表 |
| `listservicestatus -T 3000000` | 0 | PC4 的 ota_pipe 与 video_hub_pc4 |

`GetExitCode` 的静态映射还证明内部码 **120003 和 120004 均可映射到 104**。仅凭退出码不能区分二者，也不能解释为 Linux errno 104。这次 A/B 证明的是原探测预算不足，不意味着所有未来 104 都有同一原因。

已修正 `scripts/audit_g1_ota_versions.py`：固定查询清单、3 秒预算，保留官方二进制 SHA256 和端点配置校验；不接受任意命令或目标，不执行 OTA 变更。

## 官方 23 DOF 分支及当前适用性

官方[遥控说明](https://support.unitree.com/home/en/G1_developer/remote_control)更新于 2026-06-25，按运动版本提供不同手册：

| 官方目录条件 | 对应 23 DOF 手册的规定躺卧路线 | 仍需核实 |
|---|---|---|
| ≥8.4.2.222 的旧版手册（官方 PDF 未随公开仓库发布，请从宇树官网获取） | 阻尼 → 躺站（⑤） | 本机版本和 SDK 映射 |
| >8.6.0.0 的手册（官方 PDF 未随公开仓库发布，请从宇树官网获取） | 阻尼 → 自适应起身（⑩） | 本机版本；不得直接用 FSM 702 代替⑩ |

官方目录条件有覆盖范围，尚未取得本机运动版本，不自行选定分支；29 DOF 手册不用于本机。

- 躺卧与蹲姿启动的地面要求是平整、坚硬，并有规定起点；靠柜坐地未核定为允许起点。
- 椅坐启动涉及锁定站立再进入运动控制，②→③要求人工辅助扶正；地面和柜体不能代替规定椅坐支撑。
- 预备姿态约 5 秒的说明不等于起身可减速。坐姿、蹲姿说明不带平衡控制；慢速起身的速度、时长和轨迹仍未知。
- 站立模式在难以维持平衡时可能迈步，不能理解成双脚固定或电机位置锁死。`BalanceStand`、持续踏步和 `Start` 的本机进入/退出、失败恢复及回读契约仍未核定。
- `StopMove` 只发零速度目标；遥控阻尼属于模式切换；独立硬件断电急停是否存在仍未知。三者不能互相代替。

本轮将这些条件写入基础档案 v20 和 Mac 软件遥控页，只读展示。8 项运动入口保持锁定，`device_applicable` 与 `selected_manual_branch` 保留 `null`；253 项实机电机配置未用示例值填充。不能据此承诺当前姿态可安全起身或绝不摔倒。
