## 相机恢复与后续超时

接入前，Orin 没有 Intel 相机 USB 枚举和 `/dev/video*`。用户重新连接 Type-C 后，出现 RealSense D435i（`8086:0b3a`）及 `/dev/video0` 至 `/dev/video5`。现有官方 `videohub_pc4` 自动恢复 `GetImageSample` 成功回读，无需重启官方服务或重新配置相机。原始图像 1920×1080，控制台预览 960×540。

官方 SDK 中 `3102` 是请求发送失败，`3104` 是等待 API 响应超时；两者均不能独立证明相机硬件故障。[固定版本错误定义](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/rpc/internal.py)。

最终发布后进行约 **13.04 秒、24 次**只读采样：**2 次画面新鲜、22 次过期**，过期时报告 `SDK_3104`。这是状态采样结果，不是每次 SDK 请求的成功率。后续 Mac 浏览器再次显示连续更新的真实画面，已保存成功与中断两种界面。相机稳定性尚未解决，不能宣称持续可用。

最终状态快照 **12:37:56**：相机第 **925 帧**、帧龄 **220 ms**，身体反馈龄 **7 ms**；该次取图成功不抹去此前超时记录。

额外只读核查显示 USB 当前为 5000 Mb/s、`runtime_status=active`。有界内核日志记录了初次插入期间的 USB 重连；没有足够证据把后续 API 超时归因于同一原因。未修改 USB 省电设置、曝光、分辨率或 DDS 网络配置。[USB 与内核记录](G1_CAMERA_RUNTIME_READONLY_20261021.json)。

取图帧龄以请求开始时间计算，官方接口没有曝光时间。帧龄达到 1000 ms 后，控制台隐藏旧画面，实时安全证据中的 RGB 条目撤回；历史观察不会变成当前证据。

## 当前身体与官方能力状态

最终运行核查快照为 **12:35:08**：23 个关节新鲜，反馈龄 24 ms；双膝约 **161.03° / 160.01°**，IMU 横滚约 **7.85°**、俯仰约 **−3.53°**。这些值描述关节形态和机体姿态，不能确定站／坐／卧或足底承重。

- 官方 `GetFsmId` 回读 **0**，SDK 映射为 `ZeroTorque` 对应状态 ID；不代表所有电机实际力矩均为零。
- 匹配 G1 HG 类型的 `rt/lf/sportmodestate` 回读 `fsm_id=0, fsm_mode=0, task_id=4, task_time=0`。任务编号语义和动作完成语义未知，不映射成具体执行能力。
- `MotionSwitcherClient.CheckMode` 成功返回 `{"form":"0","name":"ai"}`，仅保存模式标识，不据此确认平衡控制健康。
- BMS、主板消息持续刷新，原始数组与字段完整保留。单位、比例、故障位和物理发布者尚未核验，原始 `soc` 不直接显示为已确认电量百分比，零状态不证明健康。
- `rt/arm/action/state` 与 `rt/selftest` 没有新鲜消息；无消息不解释为没有动作或没有故障。

HG `SportModeState_` 的四字段定义已与官方固定提交逐字节匹配，SHA256 为 `85dda303b93504204693cfd456e977d3a9e2f07d74c06609929f4f156cf08858`。该类型没有足底力字段，不能套用 Go2 状态布局。[官方 HG 定义](https://github.com/unitreerobotics/unitree_sdk2/blob/d1abf001220d3e5f59e00a0c4aaa595e00089a4a/include/unitree/idl/hg/SportModeState_.hpp)。

**12:27:12 的同期画面与身体快照**已写入基础档案，明确标为历史记录。画面可见瓷砖、椅轮、门和拖鞋，没有完整显示双脚及全部承重点。图像 SHA256 为 `6859e0f520a57c6c4f7460841138174e6008343c29c7e47a869d77b82e44f4b2`；相机与身体时间不是硬件同步。原始截图（截图 / 照片未公开，仅本地存档）。

## 七类证据的进展

| 类别 | 已取得的部分证据 | 仍需核定 |
|---|---|---|
| 足底接触与承重 | 新鲜关节与 IMU、可见环境 | 可信接触／载荷、双脚与外部支撑对象 |
| 动态平衡裕量 | IMU、关节速度、HG 模式与任务原值 | 校准全身状态、质心与支撑关系、动态裕量 |
| 现场地面与净空 | 新鲜时的 RGB，过期自动撤回 | 深度尺度、全身净空、摩擦、坡度、跌落边缘 |
| 实机电机限值与标定 | 已固定的官方定义及本机历史来源 | 逐电机限值、零位、当前增益、降额规则 |
| 驱动健康与电池余量 | HG BMS／主板原始回读 | 单位与比例、物理来源、故障位及降额语义 |
| 保护与失联处置 | `CheckMode` 原始模式标识 | 控制归属、现场防跌落保护、急停及失联行为 |
| 具体能力全过程边界 | FSM、HG 任务字段、既有能力目录 | 任务编号语义、进入／执行／退出／恢复完整条件 |

七项均保留 `unknown`。`execution_allowed=false`，`fall_free_guarantee=false`，`validated_action_envelopes=[]`。没有把低速度、小倾角、静止期间未摔倒或 SDK 默认阈值学习为实机安全范围。新增实机电机配置 **0 项**，`actual_config` 的 **253 个字段继续为 null**。
