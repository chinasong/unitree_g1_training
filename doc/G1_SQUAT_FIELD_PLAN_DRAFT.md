## 1. 目的与范围

### 1.1 本次只回答的可证伪问题

| # | 问题 | 可观测判据 |
| --- | --- | --- |
| Q1 | 阶段 A 吊架承重、双脚仅轻触地面时，从 FSM 0 或 1 发起蹲姿一键启动，请求是否被服务接受？ | 记录 HTTP/SDK 结果；3104 只记“结果未知”，不得当成失败或成功，也不得重发。[S4][S6] |
| Q2 | `squat_to_stand` 发出后，双路 FSM 首次一致回读的是 706 还是直接 500，耗时多久？ | `GetFsmId` 与 HG sport `fsm_id` 均为发送后的新样本且一致；706 与 500 都分别记录。代码允许 500 直接完成该步。[S6] |
| Q3 | 蹲→站和进入行走的终点，是否同时满足 23 关节静止与躯干姿态门控？ | 23 关节均满足 `abs(dq) < 0.5 rad/s` 连续 1 秒；`abs(roll)`、`abs(pitch)` 均 ≤ 0.35 rad。[S1][S6] |
| Q4 | 若未自动进入 500，显式 `start` 是否在 8 秒内双路回读 500；若已是 500，是否跳过重复发送？ | 记录请求、发送前后 FSM、双路回读与耗时；到 500 后不发任何速度指令。[S6] |
| Q5 | 从 FSM 500 执行一键停止时，是否先停止行走，再由同一次 FSM 706 请求到达蹲姿；全程有无超时、中止、异常倾斜或升温？ | 记录停止请求、FSM、姿态、23 关节、最高温度及现场姿态；706 回读不单独证明动作完成。[S1][S6] |

### 1.2 本次明确不回答

- 不验证独立站稳、“不会摔倒”、无吊架条件下的平衡能力或安全包络。
- 不验证行走：到 FSM 500 后不发送前后/横向/转向速度，随即按计划进入一键停止。
- 不验证阶段 B（吊绳松弛但仍挂着）；只有阶段 A 全部通过后，另行评审决定是否做。
- 不验证 FSM 4、L2+↑、或“L2+B 会回读 FSM 1”。FSM 4 与 L2+↑ 的本机等价性、实体遥控器 L2+B 的 FSM 回读都仍未知。[S2]
- 不验证手册按键与 SDK 调用在本机固件上的完整等价性，不推断 7301 的固件内部条件。[S2][S4]

## 2. 人员、权限与口令

至少三人，测试全过程不得兼岗：

| 角色 | 站位与职责 | 立即动作 |
| --- | --- | --- |
| 吊架员 | 位于吊架控制位，持续确认吊点、吊绳张力、机器人与人员净空；不得把手伸入关节或脚下 | 听到“停”后保持或增加到预先评审的安全承重状态，禁止放松吊绳 |
| 实体遥控器员 | 站在可观察全身且不在可能摆动/跌倒方向的位置；遥控器始终在手 | 听到或喊出“停”后，按当前状态采用手册规定的阻尼保护；运控中手册写的是 L2+B 长按 5 秒。不得把该操作口述成“FSM 1 已确认”或“硬件急停”[S2][S5] |
| Mac 操作员 | 只操作一键流程、只读监控与记录；口令未闭环不得点击 | 听到“停”后不再发起任何一键步骤；若页面仍有人工遥控授权则立即锁定，但不以软件操作替代实体遥控器保护[S3] |
| 记录员（建议第 4 人） | 使用统一时钟记录口令、请求、回读、肉眼结果和原始路径；不承担以上三项操作 | 宣读缺项，任何关键证据缺失即喊“停” |

**任何在场人员都有权喊“停”，无需解释；只有现场负责人可在原因消除并重新从前置核验开始后宣布重启。** 固定口令：

1. Mac：“准备步骤 N”；吊架员：“吊架就位”；遥控器员：“遥控就位”；记录员：“记录就位”。
2. 现场负责人：“执行步骤 N”；Mac 操作员复诵“执行”后只点击一次。
3. 任一人喊“停”后，全员复诵“停”；禁止说“继续试一次”。

## 3. 吊架条件与阶段边界

### 3.1 “承重”的现场可观察定义

阶段 A 只有同时满足以下条件才记为“吊架承重”：

| 项 | 现场判定与记录 |
| --- | --- |
| 吊绳 | 全程张紧、无可见松弛；吊点、吊带、锁扣无滑移；正面和侧面各有连续视频。 |
| 承重读数 | 若吊架有经现场认可的载荷显示，记录型号、读数、单位、采样时刻和原始文件；最低承重值/比例目前**未知，待用户决定**。没有载荷显示时，只能记“可见张紧”，不得写具体承重比例。 |
| 双脚 | 阶段 A 目标是两脚掌保持接触平整地面、无单脚悬空、无明显踩实承重迹象；禁止把手或测具伸到通电机器人脚下。仅凭画面或当前遥测不能证明足底载荷，所以记录为“轻触的现场观察”，不得提升为定量足底受力结论。[S3][S4] |
| 失效 | 吊绳出现松弛、吊点/吊带滑移、机器人由地面独立承重、单脚异常离地、吊架行程不足或机器人摆动，任一项均立即中止。 |

若现场希望采用“双脚完全离地”作为承重确认，只能在动作前、断开动作授权的静态布置阶段单独评审；本草稿不授权在一键动作中把双脚吊离地面，也不推断 FSM 706 在悬空条件下的行为。

### 3.2 两阶段

- **阶段 A（本草稿展开）**：吊绳持续承重，双脚仅轻触地面；只验证一键启动到 FSM 500 和一键停止到 FSM 706，不行走。
- **阶段 B（不在本草稿执行）**：吊绳松弛但仍挂着。仅当阶段 A 的 Q1–Q5 全部取得完整证据、无中止项，且现场另行完成风险评审和用户决定后，才能起草/执行。

## 4. 起始姿态

1. 在没有任何软件动作授权时，先让吊架承担机器人重量；具体搬运人数、吊点、吊带安装方法和断电/上电摆放顺序由吊架说明书与现场负责人决定，本资料未给出，保持未知。
2. 参照手册“蹲姿开机”图摆放：两脚掌接触平整地面、左右对称，髋膝处于明显蹲姿，躯干正对前方；正面、侧面各拍一张全身照片。手册没有给出目标关节角、蹲深或足距数值，不自行填写示例值。[S4][S5]
3. 上电后只读核验必须显示 23 个关节、有效 IMU，且一键启动起点只能是 FSM 0 或 1；`|roll|` 或 `|pitch| > 0.8 rad` 时不得启动。[S6]
4. **坐地或靠柜不算蹲姿**：手册把“蹲姿开机”和“座椅开机”列为不同路线；靠柜坐地不属于已写明路线，外部支撑和足底承重也无法由现有画面确认。[S3][S4][S5] 座椅路线实测曾在 FSM 4 后 2–6 秒内倾倒，证明“回读到位 + 关节静止”不足以证明姿态完成。[S1]

## 5. 开始前只读核验与采样

所有命令均在项目根目录运行，使用主工作区虚拟环境。下列两类采样只读取控制台；对照脚本的固定 getter 虽经 `POST /api/command`，其清单是只读操作，不取得控制权、不发送写入。[S3]

先把 `YYYYMMDD-HHMMSS` 替换为现场时间；两个输出文件不得同名或覆盖旧证据。

先执行一次只读快照；它只调用 `GET /api/session` 与 `GET /api/state`，完整原文写入指定 JSON，终端仅打印核验摘要：

```bash
.venv/bin/python - \
  .g1-deploy/research/squat-stage-a-preflight-YYYYMMDD-HHMMSS.json <<'PY'
import http.cookiejar, json, pathlib, sys, urllib.request

base = "http://127.0.0.1:18766"
opener = urllib.request.build_opener(
    urllib.request.ProxyHandler({}),
    urllib.request.HTTPCookieProcessor(http.cookiejar.CookieJar()),
)
opener.open(base + "/api/session", timeout=5).read()
state = json.load(opener.open(base + "/api/state", timeout=5))
output = pathlib.Path(sys.argv[1])
output.parent.mkdir(parents=True, exist_ok=True)
output.write_text(json.dumps(state, ensure_ascii=False, indent=2) + "\n")
telemetry = state.get("telemetry") or {}
joints = telemetry.get("joints") or []
sport = ((telemetry.get("safety_feedback") or {}).get("sport") or {})
temperatures = [value for joint in joints for value in (joint.get("temperature") or [])]
print(json.dumps({
    "output": str(output), "run_id": state.get("run_id"),
    "mode": state.get("mode"), "connected": state.get("connected"),
    "owner": (state.get("control") or {}).get("owner"),
    "armed": (state.get("manual_remote") or {}).get("armed"),
    "fsm": telemetry.get("fsm"),
    "hg_fsm": (sport.get("raw") or {}).get("fsm_id") if sport.get("current") else None,
    "rpy": (telemetry.get("imu") or {}).get("rpy"),
    "joint_count": len(joints),
    "max_temperature": max(temperatures, default=None),
    "telemetry_age_ms": state.get("telemetry_age_ms"),
}, ensure_ascii=False, indent=2))
PY
```

## 6. 阶段 A 逐步流程

软件不会自动重试，序列中止后也不会自动回退模式；3104 后只能等新鲜双路回读，不能再次发送。[S6]

| 步骤 | 谁操作 | 软件预期（FSM / 超时 / 门控） | 现场观察与记录 | 立即中止条件 |
| --- | --- | --- | --- | --- |
| A0 冻结基线 | Mac + 记录员 | 不发送动作；完成第 5 节核验并启动两套只读采样 | 记录 Asia/Shanghai 时间、run_id、发布、双路 FSM、rpy、23 关节、最高温度、吊绳/双脚状态 | 任一前置项不满足；两套采样未写出首条记录 |
| A1 一键启动确认 | 全员口令；Mac 只点击一次 | 计划只接受 FSM 0/1；启动时倾斜须 ≤ 0.8 rad。[S6] | 截图确认项、请求 ID/结果、点击时刻 | 口令未闭环；FSM/姿态/温度/吊架条件变化 |
| A2 阻尼 | Mac 自动步骤 | 若起点 FSM 0：发送 damp，目标 FSM 1，双路回读超时 8 s；若起点已是 1：跳过。官方示例在后续 706 前等待 0.5 s，但本项目序列没有单独的 0.5 s 定时项，只按自身回读与静止门控执行。[S6][S7] | 记录 SDK 结果、双路 FSM 首次一致时间、吊绳张力、足部、全身运动、温度 | 任一时刻姿态无效或 `abs(roll)`/`abs(pitch) > 0.8`；吊绳松弛/滑移；异常摆动、异响、人员进入危险区；温度 ≥70 ℃ |
| A3 蹲→站 | Mac 自动步骤 | 发送一次 FSM 706；回读 706 **或直接 500** 均可完成回读门，超时 20 s；随后 23 关节均 `abs(dq)<0.5 rad/s` 连续 1 s（最多等 10 s），终点倾斜须 ≤0.35 rad。[S6] | 分别记录请求接受、706/500 首次双路一致时刻、rpy 峰值/终值、最大 `abs(dq)`、温度峰值；肉眼记录是否实际由蹲到站 | 同 A2；另加回读冲突/过期、20 s 无目标回读、10 s 未静止、终点倾斜 >0.35 rad、动作与目标姿态明显不符 |
| A4 进入 500 | Mac 自动步骤 | 若 A3 已读到 500，则跳过显式 `start`；否则发送 FSM 500，双路回读超时 8 s；静止判据同 A3，终点倾斜须 ≤0.35 rad。[S6] | 记录是否跳过、请求结果、双路 FSM、姿态、吊绳/足部、温度；**不发送速度** | 同 A3；FSM 500 仅回读到位但动作/姿态未完成也中止 |
| A5 500 静态观察 | 全员；不操作摇杆 | 保持只读观察，持续时长由现场评审在执行前填写：**未知/待决定** | 每 2 s 样本、吊架读数、姿态、温度；不得称“行走验证” | 任何温升趋势令现场人员不安；任一通用中止条件；观察时长未预先填写 |
| A6 一键停止确认 | 全员口令；Mac 只点击一次 | 仅从 FSM 500 或 706 进入；启动前倾斜必须 ≤0.35 rad。[S6] | 确认下蹲空间、吊架持续承重、遥控器在手；记录点击时刻 | 倾斜 >0.35 rad、FSM 非 500/706、温度 ≥70 ℃、吊架/人员条件变化 |
| A7 停止行走 | Mac 自动步骤 | FSM 500 时先发软件停止行走；该步无目标 FSM，代码等待 0.3 s 后继续。软件停止只是停止速度请求，不是阻尼或硬件急停。[S5][S6] | 记录请求接受/错误、FSM 与肉眼运动；本试验原本未发速度，不据此推断实际行走制动 | 请求异常、出现运动、姿态/吊架/温度触发通用中止 |
| A8 站→蹲 | Mac 自动步骤 | 发送一次 FSM 706；双路回读目标 706，超时 20 s；随后 23 关节静止判据同上（最多 10 s）。代码未把此终点列为“站立类 ≤0.35 rad”门控，故仍须记录实际蹲姿，不能只凭 FSM 和静止宣布完成。[S6] | 记录 SDK 结果、双路 706、耗时、rpy、最大 `abs(dq)`、最高温度、正侧面视频；核对是否回到手册蹲姿 | 同 A3；或虽回读 706/静止但未实际到达预期蹲姿 |
| A9 收尾 | 吊架员 + 遥控器员 + 记录员 | 不再使用一键流程；保持吊架承重，按现场评审后的手册关机流程收尾 | 停止采样，记录两份原始 JSONL 路径、视频/照片路径和文件哈希 | 任一状态未知时不得自行追加模式命令 |

**共同软件时序**：每个动作最多先等 3 秒取得完整新鲜身体证据；SDK 返回后 1.5 秒内须有新身体样本；目标 FSM 使用各步 8/20 秒回读超时；回读后关节静止最多等 10 秒。[S6]

## 7. 中止与复原

### 7.1 任何时刻的中止条件

- 任一人喊“停”；吊架失去承重条件；机器人异常摆动、明显倾倒、单脚异常离地、碰撞风险、异响或线缆缠绕。
- IMU 无效，或任一时刻 `|roll|` / `|pitch|` > 0.8 rad；站立类步骤终点 > 0.35 rad。[S1][S6]
- 双路 FSM 冲突/过期、run_id 改变、链路失联、23 关节不全、步骤超时、关节未静止，或请求出现未预先评审的错误。
- 任一关节温度达到 **70 ℃**；这是项目保守停止线，不是允许持续到 70 ℃的目标值。一键启动阶段由软件自动中止；一键停止阶段软件**不拦截**（停止是卸载方向），本方案仍要求人工按 7.2 中止并阻尼。[S1][S8]
- 请求被接受但现场动作与目标不一致。座椅事故已经证明“请求/回读/静止”不等于动作完成。[S1]

### 7.2 中止后固定动作

1. 任何人喊“停”；吊架员保持/增加到预先评审的安全承重状态，绝不放松吊绳。
2. Mac 操作员停止后续点击并锁定软件人工遥控；不要重试、不要换路线、不要发送“回到某 FSM”。序列本身也不会自动回退。[S6]
3. 实体遥控器员按手册和当前状态执行阻尼保护；记录按键与时间，但 **L2+B→FSM 1 保持未知**，不得伪造回读结论。[S2][S5]
4. 记录员继续只读记录 FSM、rpy、关节、最高温度和现场姿态，保存原始文件；只读链路失效则记“未知”。
5. **倒地、悬吊姿态异常或目标姿态不符时，不用一键启动/停止复原。** 由吊架和现场人员稳定机器人，再按实体遥控器与现场批准的关机流程处置。[S1]
6. 温度 ≥70 ℃时不再发送任何一键动作；阻尼并安全关机后自然冷却。冷却到何值、等待多久后可重启，本资料未给出，保持未知并由用户/厂家资料决定。79 ℃事件表明倾斜的 FSM 3 可持续出力升温，不能因 FSM 到位而等待。[S1]
7. 本轮标记“中止”；只有完成原因评审、吊架/姿态/温度重新核验并新建一组证据文件后，才能由现场负责人决定是否另开一轮。

## 10. 资料矛盾、边界与缺失

| 项 | 现状 | 本方案处理 |
| --- | --- | --- |
| 官方示例 vs 项目序列 | 官方示例在 Damp 后固定等 0.5 s 再发 706；项目序列改为双路回读、身体新样本和关节静止门控，没有独立 0.5 s 等待项。[S6][S7] | 不称二者时序等价；现场分别记录 FSM 1 到 706 请求的实际间隔，交由评审判断 |
| FSM 706 的双向语义 | 手册与 SDK 将蹲→站、站→蹲都映射到 706；它不是可按目标幂等调用的两个不同 FSM。[S4][S5] | 只在已核验的路线起点调用；以现场姿态证据区分实际方向 |
| 706 后是否出现 500 | 一键代码允许蹲→站直接读到 500 并跳过 `start`；资料没有给出本机确定行为。[S6] | 作为 Q2/Q4 实测，不预填答案 |
| 实体遥控器阻尼回读 | 手册说明 L2+B 阻尼；SDK Damp 是 FSM 1；但没有证据证明实体按键必经 FSM 1。[S2] | 保护动作照手册执行，FSM 结果保持未知并只读记录 |
| 手册适用固件 | 手册分支条件明确，但本机真实运动固件仍未知；服务广告不是固件证明。[S4][S5] | 执行前作为未决风险签字，不把手册分支写成已核实 |
| 吊架“承重/轻触” | 现有遥测与相机不能测足底承重；吊架最低承重比例也未给出。[S3][S4] | 有载荷显示则保存原始读数；无显示只作定性观察，不生成比例结论 |
| 站→蹲姿态门控 | 代码对 706 停止步检查 FSM 与静止，但不应用站立类 ≤0.35 rad 终点门。[S6] | 现场仍记录 rpy 和实际姿态；异常立即中止，但不虚构软件已有该门控 |
| 温度复原线 | 70 ℃是停止线，资料没有冷却后允许重启的温度/等待时间。[S1] | 达线即结束本轮；重启条件由用户/厂家另定 |
| 软件停止能力 | `StopMove`/零速度不等于阻尼或硬件急停；本次不发送速度。[S5] | 只验证停止步骤被调用，不评价真实行走制动性能 |
