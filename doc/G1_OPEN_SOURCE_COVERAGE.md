## 已持久化的接口知识

当前 `official_capabilities` 来自 **20 个有 SHA256 的客户端/API/错误定义文件**，生成 **76 条方法记录**：

| 模块 | C++ | Python | 说明 |
| --- | ---: | ---: | --- |
| Loco | 32 | 23 | 运动、模式、参数和 getter；保留两种 SDK 的差异 |
| Arm | 4 | 2 | 包含重载及自定义动作接口，不据此确认本机均支持 |
| Audio | 6 | 6 | 声音、音量、灯光等；并非全部只读 |
| Video | 0 | 1 | 共享 videohub 取图接口 |
| AGV | 2 | 0 | 独立变体，不当作本机双足能力 |

其中 13 条只读方法记录、62 条状态修改方法记录、1 条客户端本地方法记录。**76 包含跨语言重复、别名和重载，不是 76 个实机可用动作，也不是全仓库覆盖率。** 控制台能力条目采用另一种统计粒度。

档案保存方法签名、SDK 默认参数、载荷、API 编号、源码位置和版本。SDK 默认参数仅作为接口知识；不会填入实机电机配置。23 个电机共有 **253 个实机配置字段仍为 `null`**。

这些知识保存在项目文件中，后续会话可直接加载，并非修改 Codex 模型权重。入口见 [身体基础档案](G1_ROBOT_FOUNDATION.md)和 `GET /api/body` 的 `motor_knowledge`。

## 仍需补齐

1. `.161` humanoid 的实际运行构建与运动固件版本，以及 7301 的服务端触发条件。公开客户端将 7301 定义为 LocoState 不可用，未提供内部就绪判定实现。
2. 本机电机限流、实际增益、零偏、标定、热保护等配置；模型限值和示例控制参数不能替代它们。
3. 23 DOF 各固件分支起身、姿态保持、平衡切换的本机适用条件；坐地靠柜的支撑载荷、独立站稳和停止响应仍缺证据。
4. 尚未公开或未建立只读契约的 App/私有服务能力。不会通过猜私有命令或试动作来补清单。

本轮只读核对没有执行动作、改模式、申请控制权或操作 Quantumult X。没有新增控制台执行入口或扩大运动授权；基础档案及 Orin 发布保持原版本。

本轮另从 `.161` 被动收到一帧带多个版本的服务状态，尚未完成服务名与版本绑定；见 [诊断状态流核查](G1_DIAGNOSTIC_STREAM_READ_AUDIT.md)。候选版本不写入实机参数。
