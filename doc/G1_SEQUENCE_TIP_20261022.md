教训：倒地或姿态异常后，“到达落座 FSM”不是安全终点——目标姿态与实际姿态不符时固件会持续出力并升温。这进一步支持一键停止在倾斜时拒绝执行、交给实体遥控器阻尼。

## 根因

1. **序列只判“到了没有、停了没有”，不判姿态。** 每步完成条件是双路回读到目标 FSM + 23 个关节静止 1 s。倒地后关节同样静止，所以锁定站立被判完成，序列继续弹出“人工扶直”；一键停止也对倒地的机器人发送了落座，并判完成。这是本次需要修的软件缺陷。
2. **人工扶持的位置放错了。** 手册路线是 ① 阻尼 → ② 锁定站立 → 扶直 → ③ 行走。序列把“扶直”做成锁定站立**静止之后**的暂停，而倾倒发生在发送后的 2–6 s 内——等到提示出现时早已倒下。人必须在发送锁定站立**之前**就扶住机器人。确认项“吊架或专人保护已就位”没有把这点说清，勾选它不等于有人正扶着。
3. **FSM 4 是否等价于手册 ② 仍未核实。** FSM 4 从坐姿把关节驱向站立姿态时不做平衡；它在无人扶持时站不稳是物理预期，不是固件异常。在这之前它只在设计中被假定为 ②。

## 已改（本次提交）

| 项 | 内容 |
| --- | --- |
| 倒地监测 | 序列每个等待循环（含等待人工的暂停）都检查 IMU：\|roll\| 或 \|pitch\| > **0.8 rad** 立即中止，IMU 无效也中止。中止不发任何模式，交给实体遥控器 |
| 站立终点 | 锁定站立、蹲→站、进入行走在关节静止后还须 \|roll\|、\|pitch\| ≤ **0.35 rad**（`PROJECT_TILT_RAD`），否则中止，不进入下一步 |
| 启动前置 | 躯干倾斜 > 0.8 rad 拒绝一键启动 |
| 停止前置 | 躯干倾斜 > 0.35 rad 拒绝一键停止，提示用实体遥控器阻尼。本次 ≈216 s 的落座在新规则下会被拒绝 |
| 座椅路线一键启动 | **停用**（`mode_sequence.SUSPENDED`，接口返回 `ROUTE_SUSPENDED`，驾驶页按钮置灰并说明）。座椅路线一键停止、蹲姿路线照常 |

## 现场教训

- “请求被接受 + 回读到位 + 关节静止”不等于“动作完成”。姿态是独立的必要条件。
- 软件暂停提示不能放在可能已发生危险的时刻之后；需要人扶的步骤，人要在发送之前就位。
- 倒地后的复原（落座、关机）不交给一键流程，交给实体遥控器和现场人员。
