## 结论

旧接收路径确实丢失过已到达的回复，造成假 3104；隔离轮询接收已替换八类按需查询的旧路径。最终部署后十类只读入口各六次，共 **60 次，零 3104**。这是一段实机采样结果，不是长期零超时保证。

**7301 尚未消除，运动固件版本仍未知。** 不能用修复接收路径来宣称平衡数据已可用，也不能为查询成功而试切模式。当前人工报告的靠柜坐地、双脚贴地，不等同于规定躺姿、蹲姿或椅坐，尚无核定的直接起身路线。

## 3104 与 7301 的责任边界

北京时间 20:00:14–20:00:23，在同一启动周期、FSM 0 下，对 7003–7006 进行了只读对照，并被动配对 DDS request id / api id：

| 路径 | 查询数 | 报告 3104 | 报告 7301 |
| --- | ---: | ---: | ---: |
| 旧控制台接收路径 | 16 | 10 | 6 |
| 独立进程轮询，空串与 `{}` 参数各半 | 32 | 0 | 32 |

被动观察的 **93 个请求全部配到回复**；其中 7003–7006 的 48 个回复均为 7301，包括被旧控制台报告超时的请求。因此可以定位到旧接收路径的失配/丢失问题，尚不能断言是 SDK 内部哪个线程、队列或运行时机制导致。

官方固定提交的 [G1 错误定义](https://github.com/unitreerobotics/unitree_sdk2/blob/69c04316d81ac244c314e730106e24787b3e61b8/include/unitree/robot/g1/loco/g1_loco_error.hpp)把 7301 定义为 LocoState 不可用。返回码非零时，`data` 中的 `0`、`0.0`、`[]` 均被丢弃，不能当作平衡模式、站立高度或步态相位。姿态和内部模块中哪个条件触发该错误，仍未知。

实现使用固定 getter 白名单、lease 0、独立进程轮询和 request id / api id 配对；按需查询串行，不自动重试，不回退到旧接收端。本软件进程间等待失败记为 `MODE_WORKER_TIMEOUT`，与 SDK 的 3104 分开。非零 SDK 码贯穿 HTTP、操作记录和界面，显示“查询不可用 · 值未知”。

首轮部署中音量旧路径出现过一次 3104，未取得与该次请求配对的被动回复，不能把它也认定为假超时。音量与动作清单随后一并迁入隔离进程，最终复测各六次均成功。

## 起身、姿态保持和平衡切换

接口常量是软件协议证据，不代表本机适用条件已经满足。界面已列出九类入口的来源、进入条件、反馈和缺口。

| 官方入口 | 已核对的含义 | 当前适用判断 |
| --- | --- | --- |
| C++ StandUp / FSM 4 | 站立预备入口 | 本机固件映射及靠柜坐地路线未核定，锁定 |
| C++ Squat / FSM 2 | 蹲姿入口 | 坐地不能当作蹲姿；蹲姿无站立平衡，锁定 |
| 固定 Python SDK / FSM 706 | Squat2StandUp 与 StandUp2Squat 共用转换值 | 与 FSM 4 不同，方向依赖状态；锁定 |
| 固定 Python SDK / FSM 702 | Lie2StandUp | 没有证明适用于当前靠柜坐姿，锁定 |
| C++ Sit / FSM 3 | 坐姿入口 | 不能推导可从任意地面坐姿反向站起，锁定 |
| Start / FSM 500 | 进入行走控制 | 不是从任意姿态起身的命令，锁定 |
| BalanceStand / balance 0，ContinuousGait / balance 1 | 平衡模式接口 | 当前读回 7301；不能推定已开启或尝试切换 |
| Damp / FSM 1 | 阻尼 | 不是给全身主动托举支撑；可能失去支撑，锁定 |
| ZeroTorque / FSM 0 | 零力矩 | 不提供主动支撑；不能当作安全站立状态 |

依据：[固定提交 C++ LocoClient](https://github.com/unitreerobotics/unitree_sdk2/blob/69c04316d81ac244c314e730106e24787b3e61b8/include/unitree/robot/g1/loco/g1_loco_client.hpp)、[本项目固定 Python SDK](https://github.com/unitreerobotics/unitree_sdk2_python/blob/814556d15970dd2ecf1c9984e845ca02ab07e206/unitree_sdk2py/g1/loco/g1_loco_client.py)。本轮没有浮动升级 SDK。

23 DOF 手册需先匹配运动固件：≥8.4.2.222 旧版（官方 PDF 未随公开仓库发布，请从宇树官网获取）列躺站路径，>8.6.0.0 新版（官方 PDF 未随公开仓库发布，请从宇树官网获取）列自适应起身。手册中的平整硬地、规定躺姿/蹲姿与椅坐辅助启动是具体条件，不能套给靠柜坐地。手册中约 5 秒是动作时间描述，没有证据表明可调起身速度；`SetVelocity.duration` 也不是起身速度参数。

形成可执行方案仍需：取得本机运动固件并核对对应入口；核实当前完整姿态及脚底、坐地处和柜体支撑；确认适用路线、现场防护及独立停止方式；规定逐阶段的真实反馈验收。站立控制可能因扰动踏步，不能保证脚底不动。本轮未补造脚底或柜体承重，没有执行这些阶段。

## 软件遥控器与停止边界

目录现有 **57 个条目**：模式与起身 16、手臂任务 22、声光音频 5、只读查询 10、高级控制 2，另含移动和停止。新增服务清单、包版本查询以及站立预备/蹲姿入口；完善错误码、未知值和适用条件展示。数量包含查询和通用动作入口，不代表 57 个独立动作或完整固件覆盖。

- 软件 StopMove 发送零速度，停止平移/转向目标；不等同于阻尼、断电或取消起身、手势、舞蹈，断连时也不保证送达。
- 官方文档把遥控阻尼保护称为 emergency stop；这是控制模式切换，不能由这个称呼推导独立硬件安全回路。不同版本按键与长按时序需匹配手册。
- 本机是否有独立驱动断电急停、保护延迟及无线失联策略仍未知，本轮没有实测。

**仍未完全替代实体遥控器。** 未核实的起身、模式、站高、摆腿高度和命名舞蹈，在后端最终分发处继续拒绝；参数表单不能绕过。人工遥控服务已启用，但验收期间始终无控制者、未授权运动；自主执行继续关闭。
