## 数据链路

```text
G1 D435i → 既有官方 videohub_pc4 → 官方 API 1001 GetImageSample
  → Orin 本项目独立进程轮询接收 → 单向 IPC → 当前一帧 RAM 缓冲
  → HTTP 127.0.0.1:8765 → 既有 SSH 转发 → Mac 127.0.0.1:18765
  → 浏览器实时预览 / Codex 按需快照
```

首次接入参考官方 Python SDK 的 `unitree_sdk2py.go2.video.video_client`。当前接收器沿用固定版本的官方 IDL、ChannelFactory、videohub 请求／响应主题和 API 1001；一次仅一个请求，校验响应请求 ID 和 API ID，租约 ID 固定为 0。通过 spawn 启动独立解释器，避免 fork 已初始化的 DDS；不修改 SDK 的其他接口。没有直接打开 `/dev/video*`、更改相机参数或重启官方视频服务。用户确认官方 App 可看画面，之后检查到 Orin D435i 枚举且官方取图成功；没有证明 App 是否必须一直打开。

原始输入为 1920×1080 JPEG；本项目缩放至 960×540，JPEG 质量 78，单帧上限 500 KB，采样目标上限 5 Hz。浏览器串行取图约 4 Hz，实际刷新受 Wi-Fi 与接口响应影响，后台标签页暂停取图。当前帧存于内存，不持续录像。仅预览时不额外上传；2026-10-21 新增的自主观察开启后，Mac 会把采样画面和身体状态提交至已登录 Codex 服务分析，见 [自主观察说明](G1_AUTONOMOUS_OBSERVATION.md)。

## Codex 按需观察

在 Mac 项目目录执行：

```bash
.venv/bin/python scripts/read_g1_camera.py
# 可选：另存位置；默认覆盖 /tmp 下当前快照
.venv/bin/python scripts/read_g1_camera.py --output /tmp/g1-view.jpg
```

工具仅访问本机 HTTP 入口，要求服务为真实机器人且 `read_only=true`。会读取本地会话、身体连接状态和一张新鲜 JPEG；不会连接 DDS、取得控制权或发送动作。会话只保留在进程内存；输出默认 `/tmp/g1-codex-camera.jpg` 和同名 JSON 元数据。Codex 再通过图像查看工具读该文件，按用户任务解释当前视野。已完成这条真实链路验证；当前画面主要朝向瓷砖地面，可见鞋子和椅子部件。

此快照工具提供按需视觉输入。自动语义分析已由独立 [Mac 观察进程](G1_AUTONOMOUS_OBSERVATION.md) 实现，可在网页开始 / 暂停；持续记忆、视觉定位和自主导航尚未接入。界面的“保存当前帧”仅在点击后下载当前图像到 Mac。

## 时效、隔离与断流

- 独立取图进程只请求 `GetImageSample`，单次截止时间 700 ms；失败约 800 ms 后重试。断开控制台连接会关闭本项目采样线程和子进程。
- IPC 保留原始请求时间，不为旧图重设时间戳。工作进程退出清空帧；超过 2 秒没有 IPC 更新视为进程停滞。近期计数只是接收链路测量，不代表硬件健康或动作安全。
- 请求开始后超过 1 秒的帧由服务端拒绝，浏览器过期或网络中断后隐藏旧图。快照脚本会把本次 HTTP 用时加入帧龄保守上界，过期则拒绝保存。
- **没有传感器曝光时间戳**：`timestamp_basis=request_started_at`，`sensor_timestamp=null`。显示帧龄表示取图请求以来的时间，不能证明官方服务内部缓存时长或传感器曝光延迟。
- 每次采样线程有独立来源 ID，序号递增；已启用官方相机时外部 `POST /api/camera` 返回 409，避免混入 ROS / 其他来源图像。
- 图像与相机状态接口沿用控制台认证和 `no-store`；服务只监听 Orin loopback，Mac 经 SSH 访问。

若页面等待画面，先检查“连接与配置”是否为真实 G1、DDS 网卡 `eth0`、身体反馈在线，再检查相机状态错误。官方设备暂未枚举或取图超时会显示等待 / 重试；不要因此停止或抢占官方视频服务。机器人重启后的本项目服务、SSH 转发与 DDS 恢复见 [部署说明](G1_ORIN_READONLY_DEPLOYMENT.md)。当前启动脚本已固定 `G1_CAMERA_BACKEND=unitree`；默认源码启动的相机后端为 `off`。
